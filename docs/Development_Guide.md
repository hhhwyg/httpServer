# 开发指南

## 本地工作流

1. 从 `main` 创建一个只包含单一主题的分支，例如 `fix/connection-lifecycle`。
2. 用 `debug` 预设构建并运行与改动相关的 CTest。
3. 对资源、并发或协议改动额外运行 `asan`；发现 bug 时先增加复现测试。
4. 提交前运行 `git diff --check`，并使用 `.clang-format` 格式化本次改动的 C++ 文件。
5. Pull Request 描述问题、设计选择、测试命令、风险和回滚方式。

## 约束

- 不提交 `build/`、日志、数据库凭据、token、私钥或本机配置。
- 不在一次提交中混合全仓库格式化、目录移动和业务行为修改。
- 使用 RAII 管理 fd、锁和动态资源；对关闭、超时、取消和析构路径编写测试。
- 性能结论必须附压测环境、命令、原始数据和对照组。

## 格式和静态检查

`.clang-format` 已确定新增代码的格式基线。CI 对当前提交变更的 C++ 行执行格式检查，历史代码的统一格式化仍作为独立的 Phase 4 改动处理。

`.clang-tidy` 已提供初始检查集。CI 针对当前提交变更的实现文件执行检查；历史告警不会被本轮格式迁移放大。
