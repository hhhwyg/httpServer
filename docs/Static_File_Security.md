# 静态文件安全

静态资源只能从项目根目录下的 `wwwroot/` 读取。`/` 映射到 `wwwroot/index.html`。

请求路径必须以 `/` 开始，且不能包含反斜杠、NUL 字节或独立的 `..` 路径段。校验在把 URI 拼接到静态根目录之前完成；随后服务端会解析静态根目录和目标文件的真实路径，并确认目标仍在根目录中。这样 `GET /../CMakeLists.txt` 与 `wwwroot` 内指向仓库外的符号链接都会被拒绝。

服务端只会服务普通文件，不会把目录当作资源返回。单个静态文件上限为 8 MiB；超过上限返回 `413 Payload Too Large`。为保证异步输出和 `HEAD` 语义的一致性，当前实现会将受限大小的文件读入输出缓冲区后发送。

这是正确性优先的阶段性选择。对于更大的文件或高吞吐静态分发，应在独立 response writer 中实现可恢复的 `sendfile`/分块写入状态机，并用慢客户端测试验证部分写和连接关闭行为。
